# 采掘掉落归属：实现与边界

> 代码已写，尚需编译和本轮单进程游戏验收；这不是所有资源归属问题已解决的声明。

自动熔炼、采掘掉落吸附和噬魂工具吸附经验，不再以半径内“刚生成”作为所属证明。每次真实服务端 `destroyBlock` 有独立、可嵌套且异常时释放的上下文；仅收集该次目标方块的 `playerDestroy` 期间真正成功加入世界、位置在方块附近的新掉落实体。若原版投掷者或拾取限制明确指向别人，即使它刚生成也不处理。超出本次上下文的现存物品和经验不会被熔炼、烧毁或传送。

- 每个实际掉落实体最多被一次熔炼/焦化路径改变；同一把装备的融合和单附魔路径不会把同一份物品连续转换两遍。范围按捕获时的落点判断，即使先磁吸到玩家处，后续处理也能找到同一实体；磁吸仅将合法掉落设置为该玩家可拾取，并保留剩余实体。
- 成功方块采掘后才处理实际捕获到的掉落；取消采掘、权限拒绝、缺配方和潜行暂停不应吞掉物品。真实世界按实际数据包熔炼配方决定产物，不能只因挖的是某种矿就把任意副产物变成矿锭。若产物数量不能放进一个合法堆叠，暂不转换、保留原物品并提示；木制品焦化保留该堆的数量。额外方块仍各自走正常玩家工具、耐久、掉落和权限流程。
- 捕获只覆盖同步进入 `playerDestroy` 并通过 `ServerLevel.addFreshEntity` 加入世界的实体；第三方异步掉落、其他生成接口以及已经合并到旧经验球的经验，不能证明归属时保持原样，不为了显示效果去处理其他人的资源。方块/模组在自己的同步 `playerDestroy` 内直接生成、且没有任何归属元数据的副产物被视为本次行动的产物；复杂领地/共享掉落系统仍需兼容性验证。
- 每次上下文最多捕获 256 个实体；超过后其余实体保留原样，并在玩家动作栏提示一次。该上限尚未配置化；短时间连续采掘可能覆盖动作栏上的其他提示。
- 当前修正只覆盖此处列出的采掘后处理。钓鱼、战斗和其他路径中仍可能存在附近资源扫描，不能冒称已经全部安全；见总体实现状态与审计记录。

已准备服务端探针检查真实玩家采矿、潜行暂停、旧物品及经验、其他拾取目标、先磁吸再熔炼、同一实体防重及取消采掘；其中一部分直接调度内部上下文，不等于真实双客户端、模组领地权限或异步掉落实测。嵌套、异常释放、上限提示、修改配方和大输出保留也需要单独验证。本轮尚未启动游戏。
