> 本页保留撰写时的草案和静态风险描述；当前代码与验证进度以[实现状态](FUSION_IMPLEMENTATION_STATUS.md)为准，文末旧疑点不代表后续修正已经或未经过游戏验证。

> **状态：助手设计建议，尚未被用户逐项确认、实现或测试。** 这是在现有单附魔跨界范围内设计玩法，不是取消跨界、缩小物品范围或声称当前代码已有下列行为。用户已选规则优先；发现现有代码与说明不符时，在此标为风险，不把草案写成已修复。
>
> 数据来源为仓库默认 `transmutations.json` 和 `TransmuteCatalog`：**116 个变体 ID、408 个主来源—角色绑定、23 个额外来源—角色绑定，共 431 个目录绑定**。这不是 431 种具体物品，也不是 116 个附魔 × 角色：一个变体可覆盖多种角色，一个角色又覆盖多种物品，数据包还可扩展或覆盖。下文逐 ID 设计、列出角色与额外来源，并对特殊角色细分；代码实际解析顺序、交互 API 和数据包环境仍需测试。

## 1. 不缩水：先保留解析范围，再按真实动作改写

- `classifyTarget` 先判断图腾、空玻璃瓶、鞘翅/滑翔组件、弓弩、三叉戟、重锤、盾牌、钓竿，再判断剑、矛、斧、`DIG_TOOL`、护甲和无耐久消耗物等；同一物品按实际分类优先级只得到一个角色，不能把不同角色的规则无条件叠加。
- **`DIG_TOOL` 不只是镐锹锄**：还包括剪刀、刷子、打火石、胡萝卜钓竿和诡异菌钓竿。下文为全部 28 个含 `DIG_TOOL` 的默认变体分别写出五类适配：镐/锹/锄、剪刀、刷子、打火石、骑乘控制物。对于没有自然采掘动作的物品，可通过本物品真实操作或可配置技能键形成短期势，之后由同一玩家的真实合法行动兑现；不能静默禁止，也不能声称凭空完成了采掘。普通剪羊毛、刷拂、点火、骑乘和各自耐久仍按原版执行，不为触发融合截断正常用途。
- **`CONSUMABLE` 不只是食物**：包含可食用/饮用的组件物品、普通/喷溅/滞留药水、末影珍珠、风弹、烟花、雪球、鸡蛋等无耐久物品；实际事件可能是完成食用、饮用、投掷或使用烟花，不是统一的「吃完」。模组物品按其真实组件和事件适配；没有可确认的真实消耗事件时保留物品与数据并标记待适配，不把用户的现有跨界数据删除。
- `resolveForRole` 目前拒绝消失诅咒的单附魔跨界；可损坏物品上的单附魔耐久/经验修补也不走本跨界，而使用其正常适用路径。`unending_edge` 反而明确要求载体可损坏。草案不通过改变这些条件去填数；融合中的消失诅咒是另一套已选规则。
- 角色为**目录当前范围**，不是本页临时猜测的白名单。盾牌通过真实举盾/受击，护甲通过实际穿戴者事件；鞘翅通过真实穿戴/滑翔，持有而不能穿戴的兼容物品需能通过明确主动操作使用，不得悄悄变成无效。近战、投枪、弓弩、钓竿和工具分别使用各自真实行动；一项同时覆盖多类时采用对应动作，而不是强迫穿甲或鞘翅去挖矿。第 3 节的具体设计覆盖通用角色规则。

## 2. 共同规则与消耗品细分

- 优先保留已有强力特色，再用可配置的代价、冷却、提示和归属控制风险；本页的数值是待调方案，旧效果的保留与迁移仍需逐项核对。涉及真实方块的额外操作逐格走玩家工具、附魔、耐久、掉落和权限，防递归；横刈额外范围只收成熟作物，中心及草叶原有行为不变。
- 自动熔炼只处理**本次合法行动产生且可归属玩家的真实掉落**，不以附近扫描抢走他人物品；一份掉落只能保留原样或转化一次，配方缺失即保留原样。其他允许额外产出的特色，如淘沙、海猎、消耗品补充，是明确写出的实际奖励，不借虚拟特效复制无关实体；产物、概率与上限需要经济和多人测试。
- 所有原水受保护，包括原有源水和流动水；`frost_seal` 只在采掘后允许的位置放临时封堵，不替换原水，临时冰消失不生水；邻接岩浆永久变圆石的既有玩法按用户决定保留并提示。额外受权限和可放置空间约束。下文虚拟火、冰、风、水不改方块；**原版合法点火与明确保留的真实雷电**是各自的真实行为，不能因这条虚拟效果规则无声删除或声称它们绝不造成原版后果。
- 护主、反击和随机效果区分玩家主动选定与系统自动寻找；自动目标默认不寻找玩家、盟友、驯服生物、村民或无仇恨动物；具体 PvP 与服务器规则待测。控制移动走真实碰撞，虚影不可拾取，真实投掷物不得复制；伤害事件取消/盾挡/致死的时序必须分别验证。
- **食物/普通饮品**：以服务端确认完成并实际消耗一份为准；省用成功只保留这一份，不重复发放食物效果。**普通药水**：精确保留药水 ID、组件及一份原物；如果保留了满瓶，必须与该次产生的空瓶作原子结算，不能同时复制满瓶和空瓶。**喷溅/滞留药水、珍珠、风弹、雪球、鸡蛋**：以一次真实投出和一次真实扣数为准，保留机会只针对扣掉的一件，正常冷却和一次实体效果不重复。**烟花**要区分手持使用、鞘翅推进、弩装填/发射；一次真实消耗只结算一次，不让装填和发射各返一份。
- **补充型**是有意产生消耗品的玩法，不与虚拟弹药禁复制混淆：用户已选择 `mending_replenish` **经验照常获得，同时积累补给进度**，不额外扣掉这部分经验。增长只发生在该玩家实际持有的同一组，组件完全一致且不超过堆叠上限；按物品类别设置可配置间隔和上限，具体数值与经济平衡需测试。不得从别人的经验或凭空伪造经验事件获益。`mending_xp_bottle` 是不同的转换：真实可归属经验与一个真实空瓶完成原子支付后才产出一个经验瓶，经验不能同时全额入账和全额装瓶；收瓶和经验价值需验证以避免循环。
- 不死图腾省用只在一次真正的救命成功中决定是否保留**同一件**图腾；绕过无敌的伤害仍按实际规则，不能伪造第二次救命、重复动画或提前触发消失诅咒。汲灵愈体的回复来源必须是该玩家真实获得的经验；其是否同时保留经验，以及当前文案所谓「溢出」与代码实际触发不一致，需在集中实现时核对，不擅自假称已修复。
