# 融合重设计：本轮集中决定与待办

> 以下三项由用户本轮选择，记录为设计决定；尚未据此集中修改机制代码，也未完成游戏测试。更早的专属选择、保留项和例外仍以[重设计记录](FUSION_REDESIGN.md)为准。

## 1. 原版主位：按具体机制分别处理

用户选择：**不冲突的基础原版效果保留；同一事件的同一收益重复时，针对该方向合并或替代。** 每个方向的实际衔接须单独设计，并在说明界面标清。已明确选择的专属、保留现状和例外优先；不能把第 01 组完全替代主位的规则推广到所有组合。

副位不一定是装备上独立存在的原版附魔；融合必须自行提供所需副位行为或与真实事件合并一次，不能假定副位已实体化或双重结算。

## 2. 消耗品经验修补：经验和补给都保留

用户选择**保留双收益**：玩家正常获得属于自己的真实经验，同时该经验可积累 `mending_replenish` 的补给进度，达到条件后产生一份同物品、同组件的补给。按物品类别设置可配置间隔与上限，具体数值和实现需测试；不是额外扣掉经验，也不意味着可以伪造经验或复制无关玩家的物品。

这是**有意设计的实际产物**，与禁止复制虚影和他人物品不矛盾。需要验证叠堆、物品组件、经验归属、拆堆、重登、多人和重复结算。

`mending_xp_bottle` 是另一种玩法：它把真实经验和空瓶转成经验瓶，不能把完全相同的经验同时全额装瓶和入账；不要把补给型的双收益选择错误推广到装瓶。

## 3. 忠诚 ▷ 保护：扣忠诚主位一级

用户选择：**每次成功救命，扣除触发该效果的融合对的忠诚主位一级**；保护副位等级、装备及其他附魔保留。忠诚等级耗尽时，按此前设计移除该融合，不再触发救命，需要重新融合；保护副位即使未被原版实体化，也要无损保留，如何迁移待实现。

用户原创玩法本身不变：适用于实际持握或穿戴的通用装备；真正致死时无须真实图腾、播放该物品的图腾动画；按等级决定范围并按已选规则处决合格目标。不得连带扣掉别的融合或独立附魔；扣级、救命和死亡处理必须原子且防止同次重复触发。半径公式、真实伤害类型、目标/PvP及兼容细节仍待落实。

## 其他事项

快捷键暂按总设计提供**可重绑定的主动与切换技能键**；具体数值、冷却和每个方向的最终适用对象待验证。绑定副位的付费解咒方式、解咒后融合如何保留、忠诚▷保护的范围公式、真实雷电及其环境后果，以及客户端/服务端和多人领地兼容，仍需在实现前明确；不通过静默假定来决定。
