# 第 05 组：经验淬韧与濒损续命

> **本文件不代表游戏验收。** `9c0e696` 的目标版本 build `41189921628` 与 compile-check `41189921622` 成功，包含验收探针编译和 JUnit 52/52；游戏步骤按计划跳过。探针尚未运行。数值是可调整的初始默认值，不是用户事先指定的数值。

## 两个方向与原版衔接

| 有序融合 | 实际动作 | 对象 |
| :--- | :--- | :--- |
| 修补 ▷ 耐久「经验淬韧」 | 经验球**实际修复本装备**时，有概率永久增加此件装备的耐久上限。 | 玩家主手、副手或实际穿戴的、单件可损坏装备；修补原有的经验消费与修复不重复。 |
| 耐久 ▷ 修补「濒损续命」 | 实际损耗跨入剩余 1% 时，用其他穿戴护甲的不致损耐久换经验球；将要损毁时依次花经验、饱和度、饥饿恢复本件。 | 玩家实际持握或穿戴的单件可损坏装备；其他供能装备是当前穿戴的头、胸、腿、脚护甲，不包括另一只手。 |

原版支持的主附魔仍交给原版执行，不重复投影。原版标签不支持的可损坏装备：修补使用**真实经验球**原版结算后的剩余经验与该数据包的 `repair_with_xp`；耐久使用该数据包的 `item_damage` 效果，不额外伪造固定概率。它们仅在实际玩家装备动作中生效，并不会赋予所有物品新的使用动作。数据包更改签名的有序映射时，不强行套用该专属规则。保留正常畸变分发；已适用新机制的物品不再触发两个旧专属自愈/伤害或通用矩阵，旧的不可损坏载体仍保留旧路径和数据。

融合书安装和直接融合均按可损坏装备检查，而不按原版附魔物品标签交集过滤。未被工作台识别为装备的物品仍遵循工作台已有的基本对象规则。永久上限保存在物品原版 `MAX_DAMAGE` 中，首次成长时另保存原基准，避免提取、清除或重装融合后重置上限；两项都随物品复制和编码。其他模组后续修改耐久上限、复制或重造物品时，本模组无法保证它们保留这些组件。

## 初始值与支付

- 成长基础概率 20%，每级**超出一级**的副位耐久增加 5 个百分点，最高 100%；每次增长首次基准的 0.3%，向上取整且至少 1；上限为基准的 200%。基础概率、每次千分比和上限可在签名配置中调整。单次经验球实际修补会单独判定，满耐久且没有发生修补不会判定。
- 跨入 1% 时，本件上限每 100 点转成 1 点经验（向下取整，至少 1，默认至多 64）；每点经验须由**其他穿戴护甲**合计支付 4 点耐久。按可安全支付量分摊，任何一件最多扣到剩余 1 耐久。没有其他护甲或安全额度不足时：不扣、不生成经验球；经验球进世界失败时，尽力恢复未被其他回调更改的扣款。经验球上限可调整。
- 原版耐久免耗生效之后，真实损耗即将损毁才结算救回，目标为上限的 10%（向上取整，默认每次最多 4096）。按当前**等级与进度**计算实际可花经验，不使用非余额性质的累计 `totalExperience`：1 经验恢复 2 耐久，然后每 1 饱和度恢复 1、每 1 饥饿点恢复 1。整点经验/饥饿可以向上支付，恢复量始终不超过实际付款及目标。可购买恢复量不足 1 则不付款、正常损毁；绝不扣生命。目标比例及单次上限可调整。

## 保存与跨模组边界

逐件核验装备身份、上限和损耗之后才开始护甲扣款，使用线程局部重入防护；这是对常规单服务端线程与原版实体生成的保护，不是跨模组分布式事务。其他模组可在扣耐久、资源修改、实体生成或原始耐久应用中同步重入、取消或篡改数据，可能造成扣款/退款不完整；尤其救回须在原始销毁前支付，后续第三方取消损耗时可能已付款。不能声称对任意第三方监听器原子安全。护甲支付直接设置损耗，不再次触发其耐久附魔或损坏；外挂槽位和背包里的物品不参与。
