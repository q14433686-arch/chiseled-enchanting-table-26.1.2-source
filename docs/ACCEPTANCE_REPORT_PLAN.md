# 单进程验收记录：准备状态

用户要求全部实现完成后，在一次游戏进程内逐项记录通过、失败、跳过及原因。当前尚未全部实现，**没有执行这次游戏验收**。

`ClientSmoke` 的准备工作现将现有独立服务端探针在同一集成客户端进程中分别运行，记录 `PASS`、`FAIL` 或 `SKIP`、范围和原因；第 09、11 组正反方向分别记录，另有独立畸变兼容探针。独立探针的失败不再直接终止后续独立探针，报告仍将整体烟测标为失败。多 tick 火/击退序列在后续阶段运行，未达到时标为跳过；每个独立探针前后写入检查点，客户端或世界启动、共同准备、GUI 阶段若中断，可保留此前记录和未到达项目的跳过原因。游戏尚未初始化报告器便崩溃或超时时，外部脚本生成全跳过清单，不伪造实测。`run-client-smoke/acceptance-report.md` 随烟测日志上传。

**范围限制：**探针报告仍只覆盖已准备的少量场景；每个 PASS 只代表其报告中所写的有限探针。不少探针直接调用服务端入口、没有模拟真实键盘、多玩家、概率分布、重启或第三方权限；一个探针内断言首错后，其后续断言仍不会运行。最终验收前还要按实际实现补齐独立方向、操作和保护条件测试，并改善共同初始化、GUI 与多 tick 测试的失败隔离。

另准备了 `scripts/acceptance_inventory.py`，在游戏进程结束或启动失败后，依据当次报告生成 `run-client-smoke/acceptance-inventory.md`：逐行列出默认 **1,806 有序方向、116 跨种变体及 431 个来源—角色绑定**。它只整理结果，不启动游戏，也不是游戏测试；现有有限探针 PASS 时对应整项仍为 SKIP，唯一对应的有限探针失败才标 FAIL，多方向共享探针失败不会猜测归责。没有对应结果的每一项各自写 SKIP 原因。39.1 的每个探针都比较两方向，忠诚和碎釉探针还检查其他提取/翻转操作，补给探针还检查经验瓶转换；这些首错不能归责于单个方向或变体，已按共享探针保守处理。变体与绑定是不同粒度，不能相加称为不重复玩法数量；第三方数据包及 28 类工具的五种实际动作仍需单列验收。要获得完整 PASS，必须先补齐每项的实际游戏场景并扩展报告的明确判定，不能凭索引本身声称全量完成。

原流程先启动独立服务器建立世界，再启动集成客户端，**不是一次游戏进程**。现在准备改为 `ClientSmoke` 在集成客户端内通过原版创建世界 API 创建全新平坦测试世界；CI 不再预启独立服务器。脚本拒绝已有运行目录，并创建仅供这次临时运行使用的标记；客户端在写第一个报告前先验证标记、配置目录位置、符号链接及已有输出，并在建世界前再次确认游戏目录和存档目录，拒绝已有同名世界，不会复制或复用用户存档。报告使用验证过的绝对目录而不是进程当前目录。测试会放置方块、生成实体并临时修改配置，只能在一次性世界执行。旧的 `scripts/server_smoke.py` 仍可单独用于专服兼容检查，但不属于最终单进程验收。

新的同进程创建世界流程和报告**尚未游戏运行验证**；目标编译、静态检查或准备好的 fixture 仍不能证明世界成功创建或测试通过。完整实现后，应由这一个集成客户端进程完成全部逐项验收；缺少真实多人、外部模组或无法在该进程完成的情形必须记录 SKIP 和原因，不得借用另一次游戏进程的结果充数。
