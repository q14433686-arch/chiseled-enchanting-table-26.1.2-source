# 《融合附魔》玩法与规则说明（0.6.0）

> 本页描述仓库随附的**默认数据与当前实现**，不是对所有数据包、第三方模组或服务器配置的保证。实际操作以附魔融合台的服务端报价和游戏内提示为准。目标为 Minecraft `26.1.2`、Fabric、Java 25；术语见[术语表](GLOSSARY.md)，已确认缺陷及未实测风险见[审计与建议](AUDIT_NOTES.md)。

## 一、核心概念

- **融合词条**：两个附魔组成有序的 `[主 ▷ 副]`。交换顺序会改变主副角色与可能触发的效果，但不保证每一对的反向都有独立签名。
- **签名共鸣**：特定有序组合的专属规则。默认 `signatures.json` 有 **152 条签名共鸣**：149 条精确有序配方和 3 条以主位 `*` 匹配的通配规则。未命中签名的有效组合仍可使用触发/效果矩阵；规则、等级和宿主兼容性仍须通过检查。
- **异位化形**：在受支持的宿主上铭刻一个非原生单附魔，使用单独的数据组件，不占融合用的器魂槽。默认 `transmutations.json` 有 **116 项异位化形**；不是任意附魔都能放在任意物品上。
- **器魂槽 `◇`**：一般合资格装备有 1 槽；默认黄金装备等属于 `#enchantment_fusion:innate_two_vessel_items`，有 2 槽。其他合资格装备可增加 1 槽，组件硬上限为 2 槽。双槽标签可由数据包调整。
- **畸变词条**：高风险融合失稳后生成的有代价词条，可在本台净化；不要把高风险单附魔化形失败混同为畸变，后者可能给装备添加消失诅咒。

## 二、制作与操作

### 合成配方

附魔融合台，按 3×3 排列：

```text
紫水晶碎片  书       紫水晶碎片
青金石块    铁砧标签  青金石块
磨制深板岩  磨制深板岩 磨制深板岩
```

- **融合秘典**：书 + 青金石 + 紫水晶碎片（无序）。
- **共鸣稳定晶 ×2**：紫水晶碎片 ×2 + 下界石英 + 哭泣的黑曜石（无序）。
- **扩展器魂槽**：可扩展装备放目标槽；A/B 放回响碎片与紫水晶簇（或支持的稳定晶），默认 5 级经验。具体以预览为准。

### 四槽与界面

A/B 为输入，催化槽放稳定晶或其他适用材料，目标/产物槽放装备、待净化物或融合成书的产物。空目标槽可直接凝练融合书，无需额外空白书；选择装备后界面切到铭刻操作。可从候选附魔中选择主副位；左键调序徽章交换选中的主副顺序，右键或 Shift+左键交换 A/B 物理槽。已完成的融合书或装备可使用相应的翻转、拆解、补强与净化操作，实际可用性由预览决定。

合成时材料优先从催化槽扣除，不足部分从背包扣除；稳定晶本身须放催化槽。界面悬停显示报价、材料来源与当前失稳率。主面板尺寸为 `304×218`，秘典为 `360×224`；不同语言和 GUI 缩放下可通过悬停及详情滚动阅读长内容。

### 仪式与退出

仪式由服务端工作台持有，而非画面持有。启动后按 **Esc 可关闭界面并继续**；重新打开可查看进度。发起者可再次点击操作按钮或按 Space/Enter 跳过，也可 Shift+点击按钮取消。工作台槽位在进行时锁定；区块卸载会暂停计时，发起者离线或死亡会取消，取消不消耗输入。完成时重新验证槽位、报价和规则快照，变化则拒绝执行。正常时长按操作约 1.45–1.95 秒，不同操作不同。

## 三、默认融合经济

以下是**无稳定晶、无姊妹模组特殊催化剂**时的默认融合报价逻辑；顺序从上到下，命中前一项后不再判断后项。`等级和`为主副等级之和。材料数量、经验和失败上限可配置。

| 分支 | 条件 | 默认失稳/波动概率 | 默认材料 |
| :--- | :--- | :--- | :--- |
| 互斥 | 原版或数据包认定互斥，且双方满级；未满级则不能融合 | **45%**，普通稳定晶每枚减 **13 个百分点**，最多 3 枚，底线 **8%** | 绿宝石 |
| 高阶非互斥 | 双方满级，且至少一方最高等级 ≥3 | 签名 **28%**；非签名 **22%** | 绿宝石 |
| 中阶 | 其余组合中，命中签名或等级和 ≥5 | **18% + 2% × max(0, 等级和 − 5)** | 紫水晶碎片 |
| 低阶 | 其余组合 | **0%** | 青金石 |

非互斥分支每枚普通稳定晶默认减 **18 个百分点**；系统只消耗当前报价有效需要的数量，但有数量上限。中阶并非永远 18%：例如等级和 6 时基础概率为 20%，一枚稳定晶后仍有 2% 风险。特殊的姊妹模组秘法催化剂可使支持的报价为 0 级经验、0% 风险，但并不免除其他材料；以实际预览为准。

普通波动时书卷和装备保留，默认扣除报价的 **50%** 经验等级和材料，分别向下取整，并扣除报价中使用的稳定晶。高风险**融合**失稳则产生畸变词条并按对应操作结算；高风险**单附魔化形**失稳则消耗附魔书并尝试施加消失诅咒。融合书镶入、单附魔化形、补强等有各自报价，不可直接套用上表。

### 畸变与净化

原生净化：A/B 槽留空，目标槽放含畸变的装备或融合书，催化槽默认放 **3 枚共鸣稳定晶**并支付 **25 级经验**；每次移除一个畸变，保留其纯净融合对。两项费用均可配置；兼容姊妹模组的秘法催化剂可改变该报价。

| 畸变 | 实际效果摘要 |
| :--- | :--- |
| 狂血反噬 | 追加 4.5 点魔法伤害；28% 概率自受 1 点魔法伤害。 |
| 走火雷劫 | 在目标或落点引雷；可能波及他人，并有概率额外反噬自身。 |
| 贪婪黑洞 | 有至少 3 点经验时消耗 **3 点经验**，对目标追加魔法伤害并短暂获得幸运；这里不是 3 级。 |
| 反向滑铲 | 对目标追加攻击伤害，同时将持有者向后弹开。 |
| 敌我同冰 | 25% 概率传送至目标并在可用空气中形成临时霜冰笼；并不保证完整封住所有实体。 |
| 烫手山芋 | 灼烧目标；20% 概率短暂点燃持有者。 |

## 四、世界效果与边界

- **霜封**：挖空位置邻水且该位置为空气、无活体占据时，在空位临时封堵，不替换原水。邻接的岩浆仍会永久变圆石；受世界边界与原版权限检查约束。
- **永霜轨迹**：未潜行、未浸水时，在附近源水上方的空气生成 `2/16` 格高的临时薄冰，避开活体；原水保留。冰块随时间龟裂消失，打碎或自然消散都不产生水。原有水在冰消失后仍可能自然流动；通用寒霜矩阵效果也在水面上方生成小片薄冰，潜行可暂停；原版霜冰的行为不由本模组改写。
- **采矿和收割**：范围技能在中心方块结算后逐格调用玩家挖掘流程，使用真实工具、附魔、掉落及耐久；跳过方块实体、未加载区域和不符合原版权限的方块。潜行可暂停常规范围挖掘和自动熔炼。横刈仅额外采收能确认成熟的同种作物，无法判断成熟度的作物保留。第三方保护、复杂采矿模组仍应实测。
- **自动熔炼**：使用当前熔炉配方，处理玩家本次方块采掘过程中捕获到的同步掉落；镐和斧均可潜行暂停。斧的原木默认 I 级 65%、II 级及以上 100% 转为木炭。异步掉落、其他生成接口以及超出上限的掉落保留原样；归属和多人边界仍需游戏验证，见[采掘产物说明](HARVEST_DROP_PROVENANCE.md)。
- **安全回返**：忠诚系救命锚点仅在同维度、已加载且仍有落脚与碰撞空间时尝试使用；不强制加载区块，也不把临时霜冰作为稳定地面。成功默认消耗 20 耐久、冷却 30 秒；环境及其他模组仍可能产生无法预见的危险。

## 五、配置与数据

游戏中 `/fusion config` 或可选 Mod Menu 可打开配置。单人世界所有者或具有 `enchantment_fusion:config/manage` 权限的服务器管理员可保存，其他玩家只读。修改写入服务端 `config/enchantment_fusion/overrides.json`，在合并后的数据包之上应用，校验成功后立即同步客户端；`/reload` 重新读取数据包与覆盖。数组以完整 JSON 数组替换；界面仅编辑已有字段，不创建/删除数据条目。

| 数据包文件 | 职责 |
| :--- | :--- |
| `economy.json` | 资费、失稳率、稳定晶、蓄力阈值和触发类型冷却。 |
| `matrix_profiles.json` | 默认 43 个附魔的触发与效果映射，未配置的附魔使用推断逻辑。 |
| `repulsive_pairs.json` | 默认 8 个互斥组；`base_instability_chance` 是未显式指定经济失稳率时的兼容回退。 |
| `signatures.json` | 有序对与签名 ID 的关联；相同有序对或同一通配副位不可重复。 |
| `transmutations.json` | 来源附魔、目标角色与化形 ID；同一来源/角色冲突会被拒绝。 |

目录本身是数据驱动的，但效果实现仍由 Java 中的已知 ID 处理：**新增任意 ID 不会自动创造可执行技能**。各语言文件有相同键；本轮修正过的非中文、非英文描述在缺少可靠翻译时可能暂用英文。客户端和服务端应使用同一构建，特别是网络协议或组件格式改变后。

### 技术边界

`fused_pairs` 最多保存两个有序对；持久化读取超出上限时会截断，这是兼容策略而非无损迁移。`transmuted_enchants` 保存非原生单附魔；`vessel_bonus` 保存额外槽位，`page_tier` 保存秘页层级。网络同步对 ID 长度、矩阵数量和配置大小有明确上限；配置在发布前验证并以服务端为准。保护事件、Mixin 与可选联动的实际兼容性不等同于编译成功，详见[审计与建议](AUDIT_NOTES.md)。
