本记录覆盖本轮已向玩家询问并得到选择的细项。不是全量授权，不把技术架构授权扩展为玩法/美术授权。

## 已达成一致

| 项目 | 玩家选择 | 实现约束 |
|---|---|---|
| 原版内成长 | 低级起步，研究逐级打开稳定制造 | 不要求先拿原版满级母版；旧档切换另审 |
| 学习来源 | 自行推导、解析高阶样本并行 | 同一结论、同一制造成果，不重复交学习成本 |
| 专精与上限 | 各分支可以不同上限、成长曲线 | 资格按附魔＋分支查询，不能拿一个分支上限套全部 |
| 经济 | 常规简洁，高阶按能力区分 | 不把研究总分同时乘进所有价格；不按提高后的上限摊薄旧等级 |
| 第一个目标 | 效率Ⅰ→Ⅱ＋样本解析闭环 | 不能只交解析按钮就声称研究实践可玩 |
| 实践形式 | 选择眼前作业，受限试用改良，整理适用条件 | 不刷次数；不能只剩免费试用→按确认；反馈需要说明效果与条件 |
| 页面入口 | 附魔台内独立研究页 | 现有页保留，不预设占用/遮挡现有tab与金色镶角 |
| 页面信息结构 | 先选附魔、目标等级，再看路线 | 广度、阶段不是默认塞满的完整研究树 |

此前“采掘条件与工具适配”入门课不再视为已确认；本轮未选择把它作为强制教程。

## 本轮实际实现

- `ResearchOutcomes`：稳定结论映射制造资格（附魔、分支、上限）；0表示未学会。
- `ResearchCatalog`/`ResearchJson`：可选 `outcomes` 与 `sample_analyses`，旧schema-1目录仍可读。
- `ResearchSampleAnalysis`：针对已选路线核对真实知识快照中的样本质量，记录证据但不自动完成。
- `ResearchRuntime.analyzeSample`：重新取得有权限的实时书房快照；不消费样本，不接收客户端自报质量。
- `ResearchRuntime.manufacturingLimit`：统一查询学习成果，后续生产接入这里，而非重写研究判断。
- `ResearchGoalView`：目标优先的不可变页面模型，路线只来自相关成果；明确下一步和缺失证据。
- 新增12项成果/解析测试、9项目标页面模型测试。示例Ⅱ/Ⅶ/Ⅹ只在测试中验证分支隔离，**不是已定平衡数值**。
- 修复原版木书架显式识别，调整真实探针摆放并补诊断；原运行40364870525失败于木书架计数，不能再标为全通过。

## 当前还不能说完成的部分

- 尚无真实游戏研究页、按钮、图标或最终贴图；SVG仅是信息结构审阅草图。
- 没有网络载荷/ACK/限流实现，所以不升协议、不冒称联机界面可用。
- 制造资格尚未切换旧加工门槛，不会在入口没完成时先锁死玩家现有能力。
- 效率试验能力、作业绑定、实际效果、证据采集、成果制造尚未闭环。
- 尚无正式生产目录；两路线示例目前在测试中，不是上线的课题。
- 现有大书房时间惩罚、旧维护、生产费用尚未迁移删除。

## 下一批必须具体审阅，不由开发者静默决定

1. 作业选择怎样表达：绑定工具、指定目标材料/场景、还是玩家指定小范围作业；不能以挖够数量验收。
2. 试验Ⅱ的边界：当前工具范围、离线/死亡/交易后处理、能否被其他人使用；不先决定过期倒计时。
3. 用什么实际反馈判断改良有效，怎样让“整理结论”不成为机械问答。
4. 研究页实际尺寸、tab位置、主次按钮、库存区域与窄屏；之后再选贴图方案。
5. 样本解析反馈的内容与学习难度；当前服务层不消费书，若改为消耗需明确再次审阅。
6. 效率Ⅱ制造的具体费用与旧档入口迁移，不把本轮经济方向当最终数字。

每批不超过4个相互关联决定；有重大冲突只补问一次，剩余明确暂缓，不无限问卷。
技术校验、防重放、存档与模块边界由开发者执行；具体玩法/数值/UI/美术维持人审记录。
