# 研究型附魔工坊：玩法与架构总规划

日期：2026-10-27。目标：Minecraft 26.3，发布版本仍为1.1.0。
状态：**实施规划，不是已完成清单**。本文件确定方向与验收；[底座说明](FOUNDATION.md)记录当前实现。

## 1. 产品目标与不可违反的约束

让玩家经历“发现问题—建立书房—提出假说—实践验证—掌握知识—可靠制造—探索新问题”的成长。
研究体系是唯一前置骨架；战斗效果、掉落、拆解和展示装备操作必须消费它的接口，不能各自建进度系统。

- 建设更好的书房不能让同一普通操作变慢、变危险。
- 知识广度打开阶段，相关知识深度决定专精；堆同一本书不等于增加广度。
- 成长节点之间有可感知的进展，但不以十个重复任务填满十级。
- 研究花时间在理解与行动，不花在强制倒计时、击杀/挖掘计数和反复缴材料。
- 玩家能搭建可复现的试验环境，是掌握而非漏洞；不追堵正常自动化、公共书房和交易。
- 已学会的普通加工可靠；风险来自主动选择的研究或专精，而非拥有更多藏书。
- 超限强度主要由效果适用边界平衡，不能只靠价格或可被修补抵消的损耗。
- 保存既有资产；未完成替代闭环前，不拆旧系统；最终也不能让新旧成本长期叠加。

## 2. 四条必须接通的玩法闭环

### A. 初学闭环（一个木书架即可开始）

接近附魔台 → 看见可研究问题及缺失条件 → 选择假说 → 获得有边界的试验许可 →
在实际操作中解决相关问题 → 看见观察反馈 → 回书房整理结论 → 获得可见、可使用的基础成果。

初学课题不要求先收集附魔书，否则“没有知识便不能研究”会造成起步死锁。
完成奖励必须是明确可用的研究/加工能力，不仅是另一条待解锁进度。

### B. 专精闭环

收集不同知识 → 解锁阶段课题 → 获取相关高质量样本 → 提出专精假说 → 用试验能力解决
对应场景问题 → 确认结论 → 选择专精、制造装备 → 在适合的场景获得优势。

不要求所有附魔都升到Ⅹ。数值型附魔采用渐进收益与少量关键节点；修补、精准采集等可以
被研究但不强塞虚假等级。独立专精成果使用独立课题，不把互斥假说误当成必须全收集的分支。

### C. 探索与传播闭环

环境现象/特殊遭遇/高阶样本 → 提供新问题与证据机会 → 书房解析与复现 → 稳定制造与传播。
超前宝箱书可有限使用，完整能力需研究；具体效能限制必须事前可见，不能暗中削弱。
探索重点是现象而非重复开箱；关键知识不能因服务器宝箱耗尽永久不可达。

基础知识可通过书籍学习和传播；少数高阶专精要求亲自验证。作者的研究成果能缩短他人学习，
不能借“亲自实践”要求所有人重新跑完整流程。知识分享不是漏洞。

### D. 加工与回收闭环

已掌握结论＋适当工作条件 → 透明报价 → 服务端原子扣费/写回 → 获得成品 → 使用或交易。
不消耗母版知识、不日常退阶、不等恢复。高阶材料与能力直观相关，不每做一件就重跑首次冒险。

淘汰/不合适装备 → 精确移除词条，或针对现有研究问题进行拆解 → 保留其他价值/获得相关证据。
拆解不发无限永久属性，不变成每次正式加工前必做的增益手续。

### 成长地图：玩家看到的阶段，而非开发阶段

| 玩家阶段 | 进入方式 | 该阶段真正新增的能力 | 不允许出现的卡点 |
|---|---|---|---|
| 初识 | 一木书架，无母版要求 | 理解研究、借用试验能力、完成首个可用成果 | 要先有高级书才能开始学习 |
| 建立方法 | 完成入门结论，接触数种不同知识 | 可复现试验、基础书籍学习传播、明确的常规加工 | 每种书重做同一个教程 |
| 专项研究 | 广度满足阶段条件，相关样本质量达标 | 在少数方向超越原版，选择实际情境专精 | 批量买同一本等于全部解锁 |
| 跨域突破 | 多类研究结论与相关环境证据 | 综合不同知识解释新现象，制造更高阶样本 | 所有高级能力都只靠堆书架 |
| 大书房 | 跨域成果与充足空间、收藏 | 多路线研究与生产的稳定基地、知识传播中心 | 因藏书更多而被动增加普通加工风险 |

具体书架/广度/质量阈值由首个闭环验证后写入目录，不现在把旧12/32/42门槛直接复制成新成长。
节点之间以已经得到的观察、可解释的结论和实际新增用途体现进展，不再另造刷取型熟练度条。
数值型超限等级在相关课题链内推进；知识阶段不是把所有附魔统一强制升到同一等级。

## 3. 首个可玩切片：验证“工作条件改变结果”，而非先做锋利

**暂定课题：采掘条件与工具适配。** 不把下面的试验设计冒充已获实玩认可。

- 条件：一处有效木书架、附魔台、可借用的普通工具，不需要母版知识。
- 提问：工具在不同工作条件下表现不同，试验能力能否弥补其中一种差异？
- 呈现：提供可理解的候选解释、明确试验许可与可选验证场景；不隐藏验收答案。
- 实践：针对有区别的条件进行真实作业，比较是否解决预告的问题；同一动作重复不累计。
- 能力：临时、作用范围受限，不产出可倒卖的永久超限物品，不修改原有装备的永久附魔。
- 观察：服务端真实作业事件产生语义证据；无效对照明确说明原因，失败也记录有用现象。
- 结论：回到合格书房确认，授予一个确实可用的入门研究工具/加工入口，并显示下一阶段问题。
- 限制：不以强制水下、特定稀有地点或昂贵装备卡初学；至少提供可在普通生存条件复现的路径。

先验证该切片是否产生理解和选择。若只是换皮教程打卡，修改课题，不复制到其他附魔。
最终具体试验效果必须通过API核查和场景验证，不能为了复用事件而选一个无聊任务。

## 4. 状态与职责划分

```text
课题目录（数据包） ──> 纯研究规则 <── 个人研究日志（持久化）
                         ↑     ↓
书房授权/扫描适配器 ──> 服务端研究应用层 ──> 有界视图/操作协议 ──> 研究界面
                         ↑     ↓
真实世界事件 ──> 证据适配器   试验许可/成果查询 ──> 加工、探索、拆解、超限效果
```

| 模块 | 拥有的状态/职责 | 禁止的依赖 |
|---|---|---|
| 目录与图验证 | 问题、假说、证据要求、结论、前置、版本 | 世界对象、UI、价格、副作用 |
| 纯规则与日志 | 选择、观察、结论、缺失条件；不可变快照 | 时钟、网络、物品修改 |
| 世界存储 | 世界内UUID日志、版本、原子替换与损坏保护 | 附魔战斗逻辑 |
| 书房适配器 | 当前菜单授权、有效扫描、独立知识最高质量 | 保存研究结论、扣材料 |
| 证据适配器 | 验证真实服务器事件、目标和试验条件 | 接受客户端“我完成了” |
| 试验许可 | 玩家/课题/修订绑定、能力范围、停止生效 | 永久修改被借用装备、免费输出正式成品 |
| 应用层 | 编排、限流、版本检查、调用存储 | 重写每种附魔的研究规则 |
| 协议与界面 | 缺什么、试验做什么、观察到什么、得到了什么 | 自行判定完成、逐帧全量扫描 |
| 成果消费者 | 查询解锁、可靠生产、书籍传播 | 另建经验条、复制整套研究判断 |

个人已理解、当前收藏知识、临时试验权限、正式生产权限是不同概念。不能都混成一个“等级”。
物理书提供样本与传播载体；普通母版在研究扫描中不因旧世代/锁定/磨损丢失其知识内容。
这不提前改变旧生产系统；两者只在迁移阶段统一替换。

### 状态流程与异常

- 未满足条件 → 可开始 → 已选假说 → 试验中/已有观察 → 可形成结论 → 已掌握。
- 野外观察不要求菜单保持打开；形成结论时重新授权与扫描。
- 换假说保留同修订相关观察；主动取消只放弃未完成试验，不回收已完成理解。
- 死亡/掉线停用试验能力，保留研究日志；重返后重新取得适用许可。
- 数据包改动证据语义须升课题修订；旧结论保留，旧试验不能误完成新课题。
- 删除课题不删除日志；不支持的存档版本停止写入，不空文件覆盖。
- 书房拆除/越界/维度改变/失去交互权限，不能开始或确认；不抹掉野外已记录观察。
- 同一证据重放幂等；完成奖励不重复发；正式物品扣费与写回必须同事务校验。

## 5. 机制增删与替换表

| 机制 | 最终处置 | 切换前提 |
|---|---|---|
| 研究课题、证据、个人理解 | 新增，主骨架 | 当前底座＋玩家入口＋完整课题 |
| 有边界的试验能力 | 新增 | 服务端许可、事件验证、失效规则一起完成 |
| 研究视图与知识传播 | 新增 | 有界同步、可读反馈、正式成果检查 |
| 日常母版磨损/使用次数退阶 | 退出普通加工 | 新解锁/成本完整接管，旧书资产转换后 |
| 复制世代造成持续生产劣化 | 移除其常规限制职责 | 用传播规则及首次理解替代，不重复收学习费 |
| 母版恢复计时与恢复专用维护 | 删除对应依赖 | 不再有需恢复的知识磨损；处理旧冻结/进度数据 |
| 解锁赎回费、长期禁止取书 | 删除经济锁定职责 | 正在执行的试验可取消；防误取改为免费独立功能 |
| 收藏越多导致等待/失误增加 | 删除被动惩罚 | 普通加工路径不再读取总藏书作为负担 |
| 纯倒计时、赶工献祭/降级 | 从常规研究生产退出 | 清算旧队列，明确未执行费用返还 |
| 重复交材料式研究 | 不新增 | 材料只支持合理准备与生产，不替代理解 |
| 广度/深度、书架空间 | 保留并重定义 | 重复书不刷广度；物理规模不拖慢普通操作 |
| 经验与材料报价、守恒、来源追踪 | 保留并审计 | 防内部套利，不把外部农场当作弊 |
| 顿悟与随机高阶书 | 后置审查与接入 | 不与确定研究解锁形成双重必过门槛 |
| 去附魔 | 保留精确服务，新增定向取证 | 不加通用永久养成刷取 |
| 彩虹等纯表现 | 保留、独立 | 不计入研究或价格 |
| 展示框/盔甲架加工 | 后置便利扩展 | 共用加工目标事务，不变成摆放门槛 |

“删除”是明确的目标，不是本轮已经删除。禁止同时让玩家承担旧维护成本和新研究成本作为最终状态。

## 6. 旧档迁移与发布策略

1. 先旁路加入研究，不擅自锁死旧有普通加工；开发期无正式课题时不假装已切换。
2. 完成一个可玩研究闭环和新生产通路，建立版本化迁移清单与备份建议。
3. 原有附魔、名称、染色、彩虹、收藏书内容保留；旧磨损/世代不抹掉书中知识。
4. 活跃旧队列先结清已执行步骤，未执行部分明确返还，不能默默取消或重复发成品。
5. 旧锁定解除；已经扣除的历史费用不凭空追溯返还，仍被占用的资源按可验证状态结算。
6. 旧研究日志按schema迁移；不根据玩家现有一箱同类书直接赠送全部高阶亲身实践。
7. 协议有新字段时升兼容修订，双端同时更新；在这之前不空升版本。
8. 新体系切换后删除旧生产入口对维护模块的依赖，再删除死代码、同步字段、配置和翻译。
   旧数据只读迁移器可保留一段兼容窗口，不能让已废弃配置继续影响新玩法。

迁移细节需结合实际费用收据与队列结构审计；不声称所有旧消耗都可无损逆推。

## 7. 实施顺序、验收与明确停线条件

| 阶段 | 交付 | 必过验收 | 状态（本轮起始） |
|---|---|---|---|
| R0 | 目录、状态机、存储、服务端入口 | 图、幂等、版本、重进/坏档、真实网关探针 | 已实现；181测试，旧原生结果本轮复核 |
| R1 | 真实书房授权与扫描 | 一木架起步、重复不刷广度、最高质量、关闭菜单/越界/拆台拒绝、不加载区块 | 本轮继续实施 |
| R2 | 研究菜单与有界协议 | 缺失条件清楚、选择/确认ACK、重开恢复、陈旧请求拒绝、无信息墙 | 待做 |
| R3 | 一个初学试验与实际成果 | 无母版死锁、试验真有作用、观察反馈、离线/死亡/交易不越权、成果可用 | 待做 |
| R4 | 阶段图与传播/生产 | 小书房到大书房有路径；借书有价值，专精实践非重复全流程 | 待做 |
| R5 | 旧机制迁移和删除 | 世界备份迁移、旧队列清算、无双重收费、无死配置和残留协议 | 待做 |

不能把“R0测试通过”写成“研究系统可玩”。R3之前不批量填附魔课题。R5未完成不能宣称旧维护已废除。
若一个试验只剩刷次数/跑腿/交材料，停下改试验；若一个限制靠换台拆架即可同收益绕过，改限制目的而非追堵操作。

## 8. 后置附魔内容的已定边界（不抢占研究开发）

- 高阶锋利切割专精：按身体类别和穿甲程度结算；高阶防护可克制；额外损耗主要在攻击者武器。
- 危险使用可造成上限损伤；低耐久继续强用可使锋利退阶，需预警、有效磨损结算、防连锁掉级。
- 高阶保护有不同专精；硬而脆是选项，不是全部升级的强制惩罚。
- 效率更快、使用成本可增加，但成本不是唯一平衡；耐久＋超限修补培养上限，有明确封顶。
- 身体类别、伤害、穿甲、上限损伤与恢复公式未定；必须经过代表场景验证，不以规划文字代替数值平衡。

## 9. 如何判断这套玩法是否值得继续

观察玩家第一次研究能否知道“问题是什么、怎么试、为何有效、得到什么”；第二次是否理解迁移，
而不是再看攻略抄步骤。检查完成书房后是否更好用、多人借阅是否有价值、泛用装备是否仍舒服。

自动化测试保障正确性，不能证明课题有趣。首个切片必须保留人工试玩反馈入口；不伪造实玩结论。
