# 首次统一验收：范围和复用方案

> 根据最新要求调整实施顺序：**完成细致讨论过的内容后，就进入一次游戏进程的逐项验收**。不再要求另外 1,374 个助手提案方向全部完成后才能进游戏。其他方向和单附魔跨种的既有功能、数据与适用范围都保留；本文件不是删除计划。

## 首次验收的设计范围

- **92 对专属方向（184 个有序方向）**：包括明确选择保留的原效果、用户原创、致密／破甲同效例外、已有及新增反向。已选专属不得被通用机制覆盖。
- **三种已选副位通配**：饵钓、绑定诅咒、消失诅咒，按默认目录展开为 124 个非专属有序方向。`*` 是主附魔通配，不是所有装备都可用；有具体适用对象和实际触发条件。
- **已选近战与射击语义模板**：默认目录中 124 个有序方向。按事件、目标含义和载体共用实现，不为同族每个方向另造一套状态机。专属及通配先于模板。
- 以上共 432 个有序方向，是**此次范围而非完成数**；`scripts/discussed_scope.py` 从设计索引和候选探针映射自动核对数量、按组列出缺少映射的方向。数据包可改变实际签名分派，不能由默认目录推断运行时行为。
- 单附魔跨种不被取消、删减或按融合交集限制；已明确讨论的经验补给、霜冰及安全修正等同样纳入首次验收。其余跨种保留现有实现，按真实装备动作做安全回归和后续审计；没有逐项证据不能声称 116 项都已重做或通过。

## 怎样加速而不换皮

1. **按真实事件复用事实，而不是扫描或补造**：已有的 `ConfirmedMelee`、真实耐久/经验观察、采掘掉落来源、射弹与防护观察器等统一产生可核验的动作证据。不同融合只选择与自身含义对应的事件和目标；不能把普通碰撞当成真实伤害或击退，把附近物品当作本人掉落。
2. **把共同能力按行为复用**：状态标记及过期、持续装备身份、合法目标／权限、真实资源支付、虚拟锋刃与射线、方向操作及客户端同步分别维护一个实现。相似的专属和模板使用同一底层能力，但可以配置不同触发、对象、效果、消耗及原版衔接；不能因为表面同属“攻击”而忽略亡灵／节肢、落势、穿透或真实装填的差别。
3. **用数据表和统一入口批量关联方向**：共同行为只实现和维护一次；方向映射提供主副位、专属优先、载体、目标及所需证据。无法组合的真正例外独立实现，未知证据保守跳过；不以空映射、旧通用矩阵或描述文本冒充新能力。
4. **按动作族批量编译、批量验收**：既有模板已按六方向复用；后续将相近机制聚合，而不是每写一个方向单独启动编译或游戏。单次集成游戏进程使用表驱动调用，逐方向保留独立结果；有限探针只证明其覆盖范围，多人、第三方权限、自然输入等未覆盖时注明 SKIP。
5. **安全与旧物优先**：新融合书装载及直接融合都按该方向真实能力验证并提示，不机械求两附魔原版载体的交集；已有不适用装备保留旧数据和旧效果。诅咒的新锁定／死亡删除必须有明确新旧版本界限，不能把旧装备静默转成新诅咒。真实水、方块、工具耐久、掉落、盟友及合法 PvP 约束继续执行。
