日期：2026-10-23。用户已选择“忠实全量移植 + 必要加固”。发布版本 **1.1.0**，Minecraft **26.3**，Java 25；MC/Loader/Fabric API/JEI/REI 等依赖版本保持原有 26.3 锁定值。

保留此前世界加载 schema、SDL 鼠标、结构生成安全、长度限幅、未知操作拒绝、目标菜单 ID、服务端转化目录及实际 JEI/REI 刷新等修复。

### 新增功能

- `MasterTomeWear`：母本磨损/保留/一次性消耗模式，充能显示及耗尽降级。
- `EnchantmentProvenance`：按附魔等级片段追踪表内付费来源，处理升级、转移、合并和退款。
- 新进度与布局：12/32/38 里程碑、台周空间检查、可选视线约束、可配置原版附魔台与铁砧规则。
- 稀有转化的个人探索/进度解锁；通用转化自动批处理、线性费用和产物拆堆。
- 分类配置 UI、搜索/筛选/滑块/父子选项联动、`/cet config`、`/cet reload-config`、`/cet reset-config`、Mod Menu 入口、表内及秘典入口。
- 新文案与 Wiki；11 个语言文件目前键数一致，为 493 个。新增保存反馈键在中英提供对应文案，其余语言使用英文反馈；键齐全不代表逐项经过人工翻译审校。

## 明确保留的源版默认规则

本轮没有采用方案 2 的旧档兼容默认：

| 项目 | 默认值/语义 |
|---|---|
| 配置与 datapack | `override_datapacks=true`，配置管理字段默认可覆盖同名 datapack 设置 |
| 母本 | `wear`，16 次额度，书本复制消耗 4，耗尽 `step_down` |
| 来源退款 | 外部/未标记来源比例 0.25；实际返还还受势能表、等级片段和取整影响 |
| 书架阶段 | 12 / 32 / 38；启用空间要求，视线约束可选 |
| 批处理 | 无书架门槛，按材料、XP、输入和配置上限计算，最大批量默认 64 |
| 原版附魔台 | 源默认 `books` 模式 |

**旧世界升级前请备份。** 旧版合法表内制作的物品也没有 `cet_provenance`，无法从现有物品可靠追溯其历史；本轮不会伪造旧来源标签，因此可能按未标记/外部规则减少退款。母本磨损和布局规则也会改变旧书库的维护与可用性。

统一配置仍按源版位于实例全局 `config/chiseled_enchanting_table.json`，不是每世界独立配置。附魔书堆叠上限是启动期设置，UI 标为需重启，不能把收到运行时配置误认为默认物品组件已经热更新；客户端与服务器的启动设置也应核对一致。

## 必要加固与 26.3 适配

### 输入与可选集成

- 新配置屏幕的左键、右键和拖动改用 `InputConstants`，没有重新使用 GLFW 数字编号。
- 新的屏幕导航使用 26.3 `Minecraft.gui.setScreen`；保留 overlay 事件转发及原版库存非左键处理。
- Mod Menu shim 仅供编译；binary 和 sources JAR 都排除 `com/terraformersmc/**`，不把第三方 API 类打进发布文件。实际 Mod Menu GUI 尚未运行验证。

### 网络、菜单和每玩家状态

- 独立协议升级至 **`26_3_revision_5`**；cost/live/runtime-config channel 带 revision。发布版本仍是 1.1.0。
- 服务端同时识别最早旧 cost channel 和 revision 4 的旧 channel，用于拒绝旧构建；不在旧 channel 上注册新 decoder，避免 JOIN 检查前旧包被误解码。
- 新增 opening/live 的 `cramped_library`、转化 `unlocked`、外部退款比例、母本/书架配置字段；保留集合读取限幅和 live `container_id` 判断。
- 转化目录按实际玩家构建。服务端每秒检查该玩家的解锁描述，仅在变化时推新费用/目录；当前菜单和查看器随之更新，不将某玩家的解锁状态当作全服通用值。
- 查看器使用服务端目录，并排除锁定转化；菜单仍按源逻辑提供锁定信息。其实际展示和实时刷新还需要客户端验收。

### 配置权限、持久化和确认

- LAN 不再因“非 dedicated”就放行全部玩家：只允许房主或服务端明确授权者修改，权限最终由服务端核对。
- 更新请求带独立递增 request ID；服务端返回匹配 ID 的接受/拒绝结果。GUI 不再在发送请求时就把编辑标记为保存成功。
- 单人运行中也走同一服务端授权/确认路径；客户端不再先行修改整合服务器共享的数据表。
- 保存写临时文件，原子替换目标文件；写入失败不先替换内存配置。若文件系统不支持所需原子替换，明确失败，不偷偷降级成覆盖式写入。
- 显式 `reload-config` 对损坏文件拒绝加载，不把它悄悄当作 DEFAULT 后覆盖。
- 配置变更成功后关闭已开的本模组表菜单，由原版归还输入，避免保留旧开屏快照；之后发送权威配置及费用/目录。
- 母本扣损候选与书架扫描使用相同的可选视线过滤；结构替换开关接入当前 26.3 安全处理器，而不是重新启用旧处理器。

## 尚未实测的边界

- 真实客户端配置界面：SDL 输入、overlay、暂停、修改/保存/拒绝提示、屏幕生命周期。
- 两个真实客户端的专服/LAN 权限、保存确认、丢线、解锁变化、共享母本及多人交互。
- JEI/REI/Mod Menu 的实际安装运行和 GUI；可选依赖编译通过不等于其界面已验证。
- 网络测试仍使用 headless registry fixture，不覆盖带非空 ItemStack 组件的完整双端网络往返；掉落组件检查是实际持久化/loot 路径，不是该网络测试的替代品。
- 专服 smoke 不含玩家，也没有执行配置管理命令；它证明启动/reload/loot 路径，不证明管理包、命令或真人操作已在游戏中完成。
- 平坦 smoke 禁用结构生成，不能替代旧世界、全部结构/延迟 mixin、母本耗尽与全库存溢出的交互测试。
- 原子替换测试不等于断电恢复/磁盘损坏测试；协议正常 fixture 不等于完整网络 fuzz。

因此本轮完成的是：按方案 1 合并新功能与默认规则，落实列出的必要加固，并取得编译、单元回归和真实无玩家专服证据；不宣称全部 GUI/多人场景已实测。
