# 第 07 组：火焰主位的焚印收割（候选）

仅覆盖选中旧签名 `alchemic_pyre` 的 **火焰附加 ▷ 抢夺**；数据包替换该方向的签名时，不接管替代实现。支持实际可近战的剑、斧、长矛、重锤和三叉戟，两种融合入口按同一方向校验，不适用的旧载体保留旧数据与旧效果。另一方向见[战利火种](SPOILS_SPARK_IMPLEMENTATION.md)。

## 燃烧观察与焚印

- `BurningTargetHistory` 在服务端实体真实 `baseTick` 后观察最多 4096 个正在燃烧的实体，连续采样至少 20 tick；重复同 tick 不加时，间断、重载、维度或实体身份改变会重新观察。它不点火、不修改实体，服务停止时清理。已经燃烧但没有足够连续观察的目标不会被猜测为合格。
- 合格敌人燃烧满一秒后，潜行的满蓄主手直接攻击须经许可、真实造成生命或吸收损失；伤害前与伤害后仍须有火，且完整攻击成功结束、同一物品仍在主手、目标仍存活。此时抽走该目标当下的剩余火焰并熄灭，留下该玩家和原物绑定的 120 tick 焚印；同一玩家一次最多持有一个，手持身份变化、死亡、断线、离开维度、目标卸载或过期会清理。只选择敌对生物、正在攻击玩家的中立生物或合法 PvP 玩家，保护盟友、驯服生物及村民。
- 普通命中保留原版火焰附加；原生主位正常运行，缺失原生投影的近战载体复用真实 Fire Aspect `doPostAttack`，不额外执行第二次已有主位或其他共享火焰重放。抽火在完整攻击后结算，因此包含本次原生 Fire Aspect 刷新的火焰；第三方在同一攻击中另行熄火或重新点火，归因仍不一定可区分，须兼容回归。

## 同次普通死亡战利品

同一玩家持同一武器在时限内直接击杀该目标时，复用真实伤害、死亡和 loot consumer 的嵌套作用域。只有外层攻击正常返回、真实伤害确认、同次死亡一次且 loot 调用一次，且原物确实从**该受害者本次 loot table**进入世界、身份及组件仍未变，才考虑结算。无需扫描地上物品，也不扣减原掉落；经验、装备掉落、玩家库存、领主稀有物及其他实体产物不作为奖励来源。

可获得的物品必须在可由数据包调整的 `enchantment_fusion:ember_harvest_ordinary` 物品标签内，并与该物品默认组件完全相同、可堆叠且数量有效；自定义名称、容器内容、独特组件及未列入的稀有物保守跳过。选择第一种符合条件的真实产物，额外生成 `min(该栈实际数量, 1 + (clamp(抢夺等级,1,6)-1)/2)` 件，最多三件。标记在生成前消耗；拒绝注册或异常时不再次尝试，正常产物始终不受影响。数据包扩展白名单应自行确认新物品的复制安全性；外部模组可在实体注册时移动或修改产物，现有身份检查和事件权限无法提供跨模组／断电原子保证。

## 验证边界

准备 `07-fire-looting` 独立候选探针：两入口、模拟燃烧时长、站立/未满蓄/取消/嵌套负例、抽火与真实死亡、确定性普通产物增量、无关地上物品不变、稀有物排除、保护目标及非原生火焰主位。纯单元测试检查连续时间、几何上限、签名与掉落增量；探针直接设置蓄力/潜行并人工调整观察时间，不能代表自然输入及燃烧过程。
