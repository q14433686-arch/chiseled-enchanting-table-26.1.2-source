# 第 06 组：封样择运与蓄运定标

> 两个方向均已编写；`98cd9ee` 通过目标编译及 111 项 JUnit。随后正向的来源证据收紧，最新编译状态见[总进度](FUSION_IMPLEMENTATION_STATUS.md)。**两方向都尚未在游戏中验收**；全部机制完成后才在一次游戏进程内逐项测试。

## 精准采集 ▷ 时运：封样择运

用主手可真实收获矿石的融合工具按正常方式开采指定矿石。实际 `playerDestroy` 已成功生成的精准采集矿块掉落中，最多一块被标为封存矿样；没有真实矿块掉落就不发放封样，也不再生成旧版额外矿物。封样仍是原矿块物品：可以作为物品保留、放置或转移（具体交易匹配取决于交易规则）；放下去以后它就是正常矿块，不再附带拆样选项。

选择拆样时，主手持有**对应相同时运等级的精准采集 ▷ 时运工具**，副手放**一个**封样，用现有主动技能键打开（有多技能时先用切换键选“拆开封样”）。服务器复制玩家当前真实工具，仅将副本中精准采集换成该封样的时运等级，在玩家当前位置调用该矿的当前真实方块战利品表一次；一个输入槽直接替换为一次掉落。玩家必须自己将叠成一组的封样拆出一个，不能一次重复结算多块。工具开采时已走真实耐久，拆样不再额外扣耐久，也**不额外生成经验**；原精准采集开采时是否有经验仍按实际数据包决定。

为避免不能原子交付多个掉落而复制或丢失资源，目前只接受战利品表返回一组可堆叠、与该原版矿石对应的原版矿物结果。空、多组、其他物品、超过单组上限、禁用物品或表执行异常时，不发任何结果，保留完整矿块并清除这次拆样选项，不能无限重新掷表。异常或非常规战利品表不会生成模拟矿物。拆样发生在玩家当前位置，不重现矿块原坐标、原采矿时刻和原工具快照；若数据包按位置、时间、工具其他组件定制结果，将使用当前实际工具和当前位置。重进世界需要仍持有匹配工具；找不到时仍可直接保留或放置矿块。

## 时运 ▷ 精准采集：蓄运定标

持适用融合工具时，先潜行并按主动技能键切换蓄运；启用后，**潜行真实挖矿**才尝试储存。正常得到的矿物不会全部消失：从能被归因于此次实际时运增加的部分扣除一半（向上取整），作为玩家的矿运，基本掉落保留。没有增加、材料不匹配、超额、行为不确定或权限未通过时，不扣物品、不生成矿运；正常时运掉落和经验仍按原版/数据包结算。

站立看向支持的矿石并按技能键可定标；随后**站立真实挖同类矿石**时，若其最终真实掉落的物品及全部组件与已存资源相同，就从矿运中转入最多 3 个单位（可配置），随后清除定标。不同矿物或组件不会互换，矿运不足只转移实际余额；这是把以前扣下的东西移到当前真实掉落，而不是凭空增加新产出。如果该掉落无法确认、余额不匹配或背包状态不合要求，则保留余额并提示。

为避免数据包修改后无法取回储存物，站立并移开支持矿石视线时按技能键，可直接把已存物归还到空副手，或叠入物品及组件完全相同、仍有空间的副手；空副手取最早的一类。每种完整物品/组件默认最多存 64 个、可配置到 1–256，最多 16 类；存满时增产留在正常掉落中。矿运保存在**玩家持久附件**，不属于工具，不随工具拆分或转手而复制，死亡时保留；定标和开关为临时会话，换手、换维、死亡、断线或重启后要重新操作。无法直接取回的禁用物品、损坏附件或不匹配组件不会静默兑换为其他物品。

### 实际来源与保守跳过

- 一次真实方块 loot 计算中，仅跟踪 `minecraft:fortune` 的原版 `ore_drops` 或 `uniform_bonus_count` 公式——两者在附魔等级为零时都不会增加数量。不能把 `binomial_with_bonus_count` 自带的额外轮次误算成时运增产，也不通过重掷两次战利品表猜差额。
- 必须与真实玩家、方块状态、方块坐标和当次掉落工具上下文匹配；公式结果之后，如果再经过其他不能证明无影响的 loot 函数，即使最终数量碰巧恢复原值，也放弃本次结算。原版无爆炸上下文时的 `explosion_decay` 是已知无操作例外。
- 只有与此次公式输出**同一对象**、数量和组件均未改变、实际成功加入世界的单个物品实体可交易。被拆栈、复制、变更、额外函数处理、多候选、捕获超限或没有实体时保留原掉落，不入账/不兑现。玩家、主手、姿态、维度及方向在计算前后重新检查；受保护的定标块不允许选择。额外范围开采不会自动扣存/兑现。
- 掉落实体和玩家数据属于不同存档记录：同步操作有失败回滚，但 Minecraft 不提供跨区块/玩家文件的崩溃原子事务，断电或第三方异步改写的极端情况仍需验证，不能承诺数据库式持久原子性。取回到副手则在玩家自己的存档记录内完成。

## 两方向共用的载体与范围

- 新融合及融合书装书共用动作检查：物品必须属于镐/斧/锹/锄的采掘角色，且实际能够收获至少一种支持矿石；普通斧、弓等不因为附魔适用对象的交集而被盲目允许。模组工具是否适用取决于它的真实正确工具规则。旧的不适用载体保留旧效果与数据并标注。
- 仅覆盖无方块实体的原版煤、铁、铜、金、红石、青金石、钻石、绿宝石、下界金和下界石英矿及对应深板岩矿；其他方块照常按主位处理，不伪造产出。第三方矿物、特殊方块实体与复杂数据包有意保守跳过。
- 原生精准采集或时运由原版执行；若适用工具不原生投影主位，仅在原版已复制的掉落工具上重放对应实际主位附魔，不修改正在使用的真实工具。两方向分别替代旧 `raw_ore_geode` 的额外原矿和旧 `smelt_fortune` 的自动熔炼/额外金属；旧不适用载体不被删除或重写。
- 普通 `HarvestDropCapture` 实体捕获只证明 `playerDestroy` 范围和附近生成，并不单独证明来源。封样现在额外要求一次目标 `Block.getDrops` 的真实返回列表、同一物品栈对象、实际 `Block.popResource` 创建且成功加入世界的实体，以及核对时未变化的完整数量与组件；多次或嵌套匹配、重复对象、替换／合并或超限时跳过，不根据物品种类和距离猜归属。两次观察之间被其他代码改动又恢复原样仍无法检测。蓄运另有 loot 上下文、公式和最终对象身份约束。这些注入与条件**尚未游戏验证**；模组直接创建自定义掉落将保守跳过封样，异步或有意伪造对象身份的代码不在证明范围。第三方领地、异步代码和其他接口不由 `mayInteract` 充分证明。
