# 修补跨种：补给与经验的结算边界

> 本页描述已写的实现及待验证行为，不代表已经在游戏验收。

`mending_replenish` 只在该玩家实际持握的消耗品或投掷物上生效。玩家真实入账的经验保留，同时为该玩家、该物品 ID 和全部组件相同的一组积累补给。经验球被原版修补消耗的部分并未入账，不会重复计入补给；不是扫描附近经验球，也不读取其他玩家的经验。

服务端在经验入账时结算，而非在下一 tick 比较总经验，避免先获得经验再切换持有物造成的串组。每次只处理按主手、再副手顺序遇到的第一个相关修补跨种；若先遇到经验瓶或图腾跨种，不再同时为另一手结算补给。经验瓶、图腾仍有自己的独立机制，**不因补给的双收益选择获得额外规则**。

- 补给组按物品和全部组件匹配，不按引用或仅按物品 ID 匹配；拆堆不会复制经验进度。进度保存在玩家的持久附件中，重登与死亡后预期保留，最多保存最近 32 组；超出时淘汰最久未更新的一组。转交给其他玩家的物品不携带前玩家的进度。
- 组上限计数包括该玩家背包与持握的同组件物品，不超过每个物品实际堆叠上限。堆叠已满但组仍未达上限时，使用空背包位或已有相同组的空间；例如不可堆叠药水会补到另一个槽位。不会因为背包满把补给掉到世界中。
- 达到组上限时不再累积新的补给经验；若背包没有位置，只保留最多一份待交付的阈值，之后重新持握并获得真实经验时重试，不无限囤积。
- 默认以每 22 经验补充一份食物、投掷物或其他消耗品，每 44 经验补充一份药水；各组默认总数上限分别是 64、64、64 和 4。数值是首次实现基线，并非已平衡结果。

`data/enchantment_fusion/enchantment_fusion/transmutations.json` 的 `replenish_settings` 中可分别修改 `food`、`potion`、`throwable` 和 `other` 的 `xp_interval`（1–10000）及 `group_cap`（1–256）；融合台配置界面亦可编辑这些字段。药水组件优先识别为药水，食物其次；原版珍珠、风弹、烟花、雪球和鸡蛋识别为投掷物，其余已支持的消耗品归入 other。未改变可跨种的物品范围。

单独的 `mending_xp_bottle` 保留转换玩法：只有实际可支付至少 8 点经验、真实空瓶和可交付成品的空间同时存在时，才支付经验、消耗一个瓶子并产出经验瓶。它不套用补给双收益；其经验缓冲仍是进程内状态，完整持续化和更多边界待后续核查。`mending_vitality` 沿用原有回血语义，具体经济规则未由补给决定。

待一次游戏进程验收：经验球拾取和原版修补竞争、分类配置与热重载、完整/空背包、药水组件、拆并堆、双手优先级、多个玩家、交易、死亡和重登、模组经验来源与反复发放、XP 上限和存档兼容。现有服务器探针使用直接调用和一次经验球触碰，不等价于所有真实客户端输入或多人测试。
