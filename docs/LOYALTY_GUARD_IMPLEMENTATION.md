# 忠诚 ▷ 保护：实现边界与待验收项

> 正在实现；本轮尚未启动游戏或完成游戏验收。编译、静态检查和准备好的探针不等于游戏实测。

## 动作与数值

- 仅当本人**实际持握或穿戴**符合融合容器规则的装备，且该装备有专属 `忠诚 ▷ 保护` 时，在可被原版图腾救回的致命伤害上尝试触发。背包内物品不算；不会消耗真实不死图腾。另一方向 `保护 ▷ 忠诚` 保留原来的安全锚规则。
- 单次触发只选择一件：忠诚等级最高者优先，再比较保护等级；相同等级按主手、副手、头、胸、腿、脚的顺序。成功后该融合忠诚等级减 1，生命设为 1 并施加原版图腾的状态效果；声效、粒子和**触发装备的客户端动画快照**分别发送。原版图腾禁用的伤害类型（包括 `bypasses_invulnerability`）不由此技能救回。
- 本实现暂定范围：`min(24, 3 + 2 × 触发前忠诚等级 + 0.5 × 保护等级)` 格，以触发者为中心。范围内敌对生物（包括首领）、正在攻击本人的中立生物及服务器允许的非盟友 PvP 玩家可受到处决伤害；保护村民、驯服生物、玩家宠物、盟友、旁观/无敌对象。伤害通过服务端正常事件管线，不扣目标护甲/盾耐久；被权限模组取消、首领自身阶段免疫或对方图腾救回时不强制绕过。嵌套的另一名玩家保命可照常救回，但不会连锁再次发出反击，避免无限互相触发。
- Fabric 的 `ALLOW_DEATH` 为当前实装优先级：本模组原有签名和单附魔保命检查先尝试，忠诚护主随后尝试，两者都在原版真实图腾前；与其他模组保命事件顺序、数据包修改伤害标签、真实多人 PvP、首领阶段和动画表现均待游戏验证。其他客户端看到粒子和声音；装备快照动画只发给被救者本人。

## 保存副位与旧物品

- 忠诚归零时移除**该融合对**；其他融合、装备和其他组件不主动删除。若保护没有和独立同名原版附魔或其他融合冲突，保留为装备上的原版附魔数据，等级不变，即使该载体原本不能附魔保护；原版是否在具体槽位生效仍由原版决定，不把它自动当作新的单附魔跨种。
- 若独立保护或其他融合占用同名位置，则把副位的完整 ID 和等级单独保存为 `retained_enchants`，悬浮提示中可见但不另外触发效果。冲突消失后，装备进入玩家手持/穿戴或背包检测时自动恢复至原版附魔数据；此期间不能将这份保留项作为独立候选选择，不能擅自覆盖或合并独立保护。每件最多保留 64 项：空间满且无法安全恢复时，此件不触发，玩家收到提示；有其他可用装备时仍可尝试。
- 新融合若确由本模组在空位创建原版忠诚投影，记录投影等级。只在标记、实际原版等级、融合等级一致且没有其他融合共享忠诚时扣减或删除投影。旧装备没有来源标记，或等级/共享关系不明确时，只改融合数据，保留原版忠诚，以免误删可能独立存在的附魔。该保守策略可能使旧三叉戟在耗尽融合后仍保留一条原版忠诚；需要玩家选择是否自行处理。外部模组若恰好把投影删除后又写回相同等级，单靠此标记无法识别，仍需兼容测试。
- 翻转、拆出和姊妹台单项移除时也只删除可确认归属的忠诚投影；显式全量洗附魔或原版砂轮仍按其全部清除语义工作。已保存的保留项不被无意抹除。物品/组件格式变更后客户端与服务端应使用同一构建。

## 验收未完成

需要在最终那**一次游戏进程**中逐项记录：双手/四件防具、背包不触发、多件优先级、非致死/被取消/绕过无敌伤害、真实图腾不扣、等级递减与归零、冲突保留及重载恢复、独立附魔和双融合、装备动画、正常实体/中立/宠物/村民/盟友/首领、合法 PvP、领地及其他保命模组、受保护目标和自身护甲耐久、旧装备与数据包热重载、网络同步与客户端版本。单人探针无法覆盖的项应标明跳过及原因，不得记为通过。
